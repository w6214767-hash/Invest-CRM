# ИнвестСкан: самостоятельное приложение, версия 0.2

Реализация в ветке `codex/investscan-standalone`. Эта версия начинает полноценную разработку по согласованной концепции. Это работающие API и интерфейс с сохранением данных; полная автоматическая система поиска по внешнему рынку ещё не запущена.

## Уже реализовано

- Отдельный React-интерфейс в стиле Штаба по предоставленному скриншоту: собственное меню, адаптивная вёрстка, постоянная кнопка возврата на `https://shtab.ugsdom.ru/#platform`.
- Возможности: квартиры, дома, участки, коммерция; фильтры по типу, району, цене, площади, стадии, подтверждённой срочности, исключениям; избранное и сохранённые поиски.
- Реальные записи в базе: ручное добавление, атомарный импорт до 500 объектов из JSON/CSV, предварительный просмотр CSV/JSON, повторяемость по `source + external_id`, история цен. Повторный импорт обновляет цену/время наблюдения/ссылку; остальные поля не перезаписывают ручную работу аналитика.
- Отдельные сущности объекта и объявления источника. Совпадения кадастровых номеров показываются как возможные дубли. Автоматического объединения разных объявлений нет.
- Карта Leaflet/OpenStreetMap по указанным координатам. Текст всплывающих карточек безопасно вставляется как текст. Автоматического геокодирования адресов нет.
- Расчёт предельной цены покупки, расходов, резерва, проектной прибыли и рентабельности. Зависимые от покупки затраты и проценты учитываются в формуле лимита. Сценарии изменения цены продажи −10%, 0%, +10%.
- Предварительные аналоги из собственной базы: отдельные объекты того же типа, района и близкой площади; для земли одинаковый ВРИ. Минимум три аналога; исключение самого объекта и его кадастровых дублей. Используются цены предложения, а не цены сделок. Свежесть считается по наблюдению объявления, а не по изменению стадии.
- Проверки с обязательным основанием, автором и временем; отдельные проверки земли и подъезда/коммуникаций. Цена и факт юридической чистоты автоматически не подтверждаются.
- Переговоры: заметки, итоги звонков/осмотров, локальные черновики; задачи, ответственные, сроки и завершение. Внешняя отправка сообщений не выполняется.
- Стадии от нового объекта до выкупленного/проданного. Переходы контролируются сервером. Для решения о выкупе и покупки нужны все проверки, актуальный расчёт и покупка в пределах лимита. Фиксация покупки и продажи доступна собственнику.
- Заявки покупателей и подбор совпадений по типу, площади, району, бюджету. В подборе участвуют активные заявки, обновлённые за 30 дней. Контакт с покупателем и подтверждение интереса остаются отдельным действием.
- Аналитика воронки, срочности, незавершённых проверок, просроченных задач и журнал действий.
- Собственный сервер FastAPI и схема данных `is_*`, миграция Alembic. Прежние таблицы Invest-CRM сохранены без переноса/удаления данных.
- OIDC-клиент для общего провайдера идентификации Штаба: Authorization Code + PKCE, проверка ID token библиотекой Authlib, индивидуальные серверные сессии, CSRF и роли `owner / analyst / viewer`. Пользовательские пароли в новом интерфейсе не создаются.
- Самостоятельный Docker Compose: PostgreSQL, миграция, API, frontend, gateway; отдельные сеть/том, лимиты памяти, health/readiness, запуск API после миграции. Скрипты резервного копирования и пробного восстановления в новую БД.
- Активная интеграция Bitrix24 удалена. Исторические колонки старой БД сохранены, чтобы не разрушать данные.

## Что ещё не подключено и не должно считаться готовым

1. Кнопка в работающем Штабе: его исходный репозиторий и авторизация пока не найдены в доступном контексте. Сам Штаб в этой ветке не изменён.
2. Общий провайдер SSO не настроен; вход с настоящим Штабом ещё не проверен. Провайдер должен быть общим для обоих приложений. Это не передача JWT Штаба в URL и не общий cookie на все субдомены.
3. DNS `invest.ugsdom.ru`, сертификат, VPS и боевой запуск не настроены. Имя домена проектное.
4. Автосбор Avito, ЦИАН, Домклик, торгов, банковских активов и партнёрских предложений. В этой версии вход данных — ручной и файловый; сохранённые поиски фильтруют свою базу и пока не запускаются фоновым сборщиком.
5. Автоматический кадастр/ЕГРН, хранение и OCR документов, оценочные модели CatBoost, фотоанализ, геозоны, собственные формы срочного выкупа и кабинеты партнёров.
6. Доставка уведомлений, постоянные фоновые задания, очередь, ежедневный отчёт в 09:00 МСК и реальные интеграции EspoCRM/Штаба. API-контракты расширяются по мере доступа к этим системам.
7. Фактические платежи, резервы капитала, расходы после покупки, подтверждённая прибыль и управление портфелем. Текущий раздел сделок показывает стадии и цены предложения, а не бухгалтерский учёт.
8. Централизованный logout/back-channel logout провайдера. Выход из этой версии отзывает локальную сессию ИнвестСкана; сессия провайдера и Штаба может сохраняться. Для отключения пользователя локально предусмотрен `POST /api/v1/investscan/auth/revoke/{identity_id}` (только собственник). Изменения роли на провайдере применяются при следующем входе; обычная сессия действует до 60 минут.
9. Браузерная визуальная проверка, контейнерный запуск, PostgreSQL-нагрузка и восстановление на VPS пока не выполнены в этой среде. Их нельзя заменять фактом успешных SQLite-тестов и сборки.

## Локальный запуск

Из корня репозитория (Python 3.11+ и Node 22):

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cp .env.example backend/.env
```

В `backend/.env` задайте собственный `SECRET_KEY`. Для локальной разработки на своей машине можно явно включить `INVESTSCAN_DEV_AUTH=true`; на доступном извне сервере это запрещено. Пустая рабочая база создаётся миграциями; учебные объекты автоматически не добавляются.

В первом терминале:

```bash
cd backend
../.venv/bin/alembic upgrade head
../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором:

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

Откройте `http://localhost:5173`. В режиме явной локальной разработки доступна кнопка без отдельного логина/пароля. В production этот способ запрещён; без подключённого SSO приложение показывает понятный экран настройки и закрывает данные.

## Подключение единого входа

Протокол основан на [официальной интеграции Authlib со Starlette](https://docs.authlib.org/en/stable/oauth2/client/web/starlette.html). Используется конфиденциальный OIDC-клиент, PKCE S256 и подписанный ID token.

1. Найти код Штаба и текущего провайдера идентификации. Если общего провайдера ещё нет, сначала подключить к нему Штаб; один клиент ИнвестСкана не создаёт SSO сам по себе.
2. Создать в общем провайдере отдельный confidential client для ИнвестСкана с Code Flow и PKCE S256.
3. Разрешённый redirect URI: `https://invest.ugsdom.ru/api/v1/investscan/auth/callback`. Адрес должен точно соответствовать `APP_URL` и фактическому домену.
4. Передавать в подписанном ID token массив `investscan_roles`: `owner`, `analyst` или `viewer`. Отсутствие роли означает отказ; роли не назначаются по названию почтового домена. Наибольшая из перечисленных ролей имеет приоритет.
5. Настроить только серверные `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `SECRET_KEY`, `APP_URL`. Секреты нельзя включать в React/VITE или в Git.
6. Кнопка Штаба ведёт на `https://invest.ugsdom.ru/`. В текущем интерфейсе при отсутствии локальной сессии есть кнопка продолжения с учётной записью Штаба. Провайдер использует уже существующую сессию пользователя; второго пароля приложения нет. Автоматическое перенаправление без промежуточной кнопки можно включить после проверки общей сессии и исключения циклов редиректа.
7. Постоянная кнопка возврата ведёт на `SHTAB_URL`. Глубокий адрес объекта сохраняется в OIDC state и восстанавливается после входа; внешние адреса возврата отбрасываются.
8. На всех reverse proxy отключить логирование query-параметров callback: они содержат одноразовый code/state. В боевом API запускайте uvicorn с `--no-access-log`, либо фильтруйте callback в системе журналирования.

## Запуск на отдельном VPS или изолированным стеком на VPS2

Подготовить корневой `.env` на сервере: `ENVIRONMENT=production`, реальный HTTPS `APP_URL`, точный issuer, клиент/секрет SSO, длинный случайный `SECRET_KEY` и случайный hex `POSTGRES_PASSWORD`. Не оставлять шаблонный секрет. Compose принудительно запрещает development auth.

```bash
docker compose --env-file .env -f deploy/investscan/compose.yml config --quiet
docker compose --env-file .env -f deploy/investscan/compose.yml up -d --build
docker compose --env-file .env -f deploy/investscan/compose.yml ps
```

Gateway слушает только `127.0.0.1:8093`; PostgreSQL и API наружу не опубликованы. Настроить HTTPS-виртуальный хост текущего VPS reverse proxy по `deploy/investscan/vps-proxy.conf.example`. Не заменять конфигурацию всего Штаба/CRM этим примером.

Старый `deploy/docker-compose.yml` и автоматический workflow `deploy.yml` относятся к прежнему окружению. Для этой ветки создан самостоятельный стек; до подключения инфраструктуры его не следует незаметно подменять в старом workflow. GitHub Pages не поддерживает серверную БД и SSO, поэтому автоматическая публикация прежней статической демоверсии отключена в коде этой ветки.

```bash
scripts/backup-investscan.sh
scripts/restore-check-investscan.sh backups/<имя-файла>.dump
```

Скрипт проверки восстановления создаёт новую БД; рабочую БД не перезаписывает. Внешнюю копию бэкапа, расписание и ограничение доступа к ним нужно настроить на сервере. Копия на том же VPS не защищает от потери VPS.

```bash
cd backend
../.venv/bin/python -m pytest tests -q
../.venv/bin/ruff check app tests
../.venv/bin/ruff format --check app tests
```

```bash
cd frontend
npm ci

```

Проверить на реальном стенде: вход из Штаба и прямой ссылки; отказ пользователю без роли; отзыв доступа; CSRF; восстановление глубокой ссылки; добавление и повторный импорт; изменение цены и устаревший расчёт; запрет покупки до проверок; перезапуск API/БД; сохранность данных; backup/restore; адаптивность экранов; пустые и ошибочные состояния.

## Результат проверки этой версии — 06.09.2026

- 40 серверных тестов прошли, включая Code + PKCE с локальным OIDC-провайдером, реальной RSA-подписью, отказом при неверной audience/отсутствующей роли и повторном state.
- 3 теста CSV/JSON прошли; production-сборка React/Vite успешна.
- Ruff: проверка и форматирование прошли.
- Миграции применены на отдельной SQLite-базе; Alembic не обнаружил расхождений со схемой моделей.
- Конфигурация Compose разобрана, проверены изоляция сервисов, локальная публикация gateway и запрет development auth. Bash-скрипты прошли синтаксическую проверку.
- Docker, PostgreSQL, реальный провайдер Штаба и браузерная приёмка здесь не проверены. Боевая публикация не выполнялась.

## Следующие блоки реализации

1. Получить репозиторий/настройки Штаба, подключить SSO, DNS и VPS; выполнить браузерную приёмку.
2. Подключить первый подтверждённый канал реального рынка с разрешённым доступом, очередью, повторными попытками и историей наблюдений; затем остальные источники.
3. Расширить канонические объекты: безопасное объединение/разъединение дублей, история снятия/повторной публикации, версии источников.
4. Добавить хранение документов, OCR, кадастровую/геопроверку, реальные сопоставимые сделки, калибровку оценки и ликвидности.
5. Уведомления и отчёт 09:00 Europe/Moscow; собственные входящие заявки, партнёры, покупатели и API EspoCRM.
6. Реальные денежные операции и портфель, подготовка/перепродажа, контроль итоговой прибыли.

Полная функциональная концепция из согласованного плана остаётся целевым объёмом; перечисленные ограничения этой версии его не отменяют.
